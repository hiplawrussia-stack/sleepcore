# FHN + STDP: Осцилляторные нейронные сети для SleepCore

**Дата:** Январь 2026
**Источник:** Bukh A.V., Shepelev I.A., Vadivasova T.E. "Training oscillatory FitzHugh–Nagumo neural networks with STDP: Dynamics and performance" — *Chaos, Solitons & Fractals*, 2025.
**PII:** S0960077925016273
**Ссылка:** https://www.sciencedirect.com/science/article/abs/pii/S0960077925016273
**Приоритет:** Research Backlog (post-launch, Q3 2027+)

---

## Ключевые результаты статьи

- Нейронная сеть из **осцилляторных FitzHugh–Nagumo нейронов** обучена через **STDP** (spike-timing-dependent plasticity)
- **Time-delayed couplings** повышают биофизическую правдоподобность
- Формируется функционально значимая **разреженная структура** (sparse connectivity)
- Точность классификации ~82% на элементарных изображениях
- Пластичность из собственной динамики нейрона — без мемристоров
- Выходные нейроны реагируют на **кумулятивное возбуждение** (несколько импульсов во временном окне), а не на одиночный спайк

## Идеи для применения в SleepCore

### Идея 1: Time-delayed oscillators для циркадной модели

**Контекст:** Текущий Digital Twin (PLRNN по Durstewitz) моделирует динамику сна как кусочно-линейную RNN. Циркадные ритмы — это связанные осцилляторы (SCN + периферические часы) с задержками.

**Применение:** Заменить или дополнить PLRNN компонентом на основе связанных FHN-осцилляторов с time-delays для моделирования:
- Циркадного ритма (Process C, ~24 ч)
- Ультрадианного ритма NREM/REM (~90 мин)
- Взаимодействия SCN с периферическими часами (задержки 1-4 ч)

**Релевантные модули:** `src/circadian/`, `src/sleep/`, `packages/cognicore-engine/ (mirror module)`

**Сложность:** Высокая. Требуется валидация на полисомнографических данных.

---

### Идея 2: FHN бистабильность для модели flip-flop сон/бодрствование

**Контекст:** Модель Saper et al. (2005) описывает переключение сон ↔ бодрствование как flip-flop — два взаимно ингибирующих центра (VLPO ↔ TMN/LC/DR). FHN-осциллятор нативно поддерживает бистабильность.

**Применение:** Биофизически обоснованная модель для предсказания:
- Момента засыпания (SOL prediction)
- Ночных пробуждений (WASO prediction)
- Влияния SRT на порог переключения (давление сна сдвигает бифуркацию)

**Релевантные модули:** `src/sleep/services/PATAdapter.ts`, `src/sleep/services/PhenotypingService.ts`

**Преимущество:** Объяснимость — бифуркационная диаграмма FHN наглядно показывает, почему пациент не засыпает (недостаточное давление сна) или просыпается (нестабильность).

---

### Идея 3: STDP как модель формирования привычек сна в CBT-I

**Контекст:** STDP — биологическое правило: "нейроны, которые стреляют вместе, связываются вместе". В CBT-I формирование связи "кровать = сон" (stimulus control) — аналогичный процесс.

**Применение:** Математическая модель прогресса пациента в SCT/SRT:
- Сила ассоциации "кровать → сон" растёт по STDP-подобному правилу
- **Кумулятивное возбуждение**: одна хорошая ночь не формирует привычку, но 7+ ночей — формируют (аналогия с порогом кумулятивного возбуждения из статьи)
- Можно предсказывать, когда привычка "закрепится" (когда синаптический вес превысит порог)

**Релевантные модули:** `src/cbt-i/engines/StimulusControlEngine.ts`, `src/cbt-i/engines/SleepRestrictionEngine.ts`

**Преимущество:** Персонализация — у разных пациентов разная "скорость STDP" (скорость формирования привычек).

---

### Идея 4: Sparse connectivity для оптимизации графа интервенций

**Контекст:** Thompson Sampling выбирает из 12 SLEEP_ACTIONS. Полный граф связей "состояние → действие" перенасыщен.

**Применение:** STDP-подобный pruning для Thompson Sampling:
- Начать с полного графа (все интервенции доступны)
- По мере накопления данных "обрезать" неэффективные связи (аналог sparse structure из статьи)
- Результат: для конкретного пациента система "знает", какие 3-4 интервенции работают

**Релевантные модули:** `src/platform/SleepCoreAdapter.ts`, `packages/cognicore-engine/ (intervention module)`

---

### Идея 5: Объяснимость для регуляторных требований

**Контекст:** FDA/CE Mark требуют объяснимости AI-решений (EU AI Act, PCCP). Текущий SHAP-style attribution в CogniCore хороший, но для нейросетевых компонентов нужен дополнительный подход.

**Применение:** FHN-сети более интерпретируемы, чем deep learning:
- Бифуркационные диаграммы показывают "почему" система приняла решение
- Фазовые портреты визуализируют состояние пациента
- STDP-веса показывают "что система выучила" о пациенте

**Релевантные модули:** `packages/cognicore-engine/ (explainability module)`
